# 移植フェーズ 設計書

旧版（`_prev/`，素の JavaScript + Leaflet）を Next.js に移植し，Vercel で公開できる状態にするための設計．
機能のパワーアップは次フェーズで別途設計する．

## 1. ゴールと範囲

**ゴール**：旧版の機能をすべて Next.js に移し，Vercel で公開できる状態にする．

| 含める | 含めない（次フェーズ以降） |
|---|---|
| 旧版の全機能（経路を描く・確定・やり直し・保存・削除・体重入力） | ログイン，DB 保存，URL での共有 |
| 経路探索を OpenRouteService（ORS）の徒歩ルートに変更 | 坂を避けるルート，勾配の色分け，逆算モード |
| サーバー側で並列に取得して高速化 | 自転車専用ルートでの計算 |
| 旧版のバグ修正 | 利用回数の制限 |

### 旧版から直すバグ

1. 徒歩のつもりで車のルートを使っていた（OSRM のデモサーバーは `foot` を無視して車で経路を返す）→ ORS の `foot-walking` に変える．
2. 経路の点を間引くときに終点が落ちていた → 始点と終点を必ず残す．
3. 59.6分が「60分」と表示されていた → 「1時間0分」と表示する．
4. 体重を変えるたびに標高を取り直していた → 取得済みの標高で計算し直すだけにする．
5. 外部 API を最大110回，1回ずつ順番に呼んでいた → 経路は1回，標高は10本ずつ並列に取る．

## 2. 全体構成

```
ブラウザ（クライアントコンポーネント）
  │  クリックした経由点を POST /api/plan に送る
  ▼
Route Handler  app/api/plan/route.ts   ← ORS_API_KEY はここでだけ使う
  ├─ ORS：経由点（最大50点）を1回のリクエストで徒歩ルートにする
  └─ 国土地理院：ルートを50点に間引き，標高を10本ずつ並列に取る（結果はキャッシュ）
  │  {経路の座標, 断面図用の点と標高} を返す
  ▼
ブラウザ：体重を使った消費カロリーと所要時間の計算，描画，localStorage への保存
```

計算をブラウザ側で行うのは，体重を変えたときに通信せずに即座に結果を変えるため．

## 4. API 仕様：`POST /api/plan`

### リクエスト

```json
{ "waypoints": [{ "lat": 35.18, "lng": 136.91 }, …] }
```

- 2点以上500点以下．zod で検査する．
- 51点以上あるときは，サーバー側で50点に間引いてから ORS に送る（ORS の1リクエストあたりの上限が50点のため）．

### レスポンス（200）

```json
{
  "coords":  [{ "lat": …, "lng": … }, …],
  "profile": { "points": [ …50点 ], "elevs": [ …50個 ] }
}
```

### エラー

本文は `{ "error": "日本語のメッセージ" }`．

| 状況 | ステータス | 表示するメッセージ |
|---|---|---|
| 入力が不正 | 400 | 経由点は2点以上指定してください |
| 道から離れた点がある（ORS のエラー 2010） | 422 | 道の近くをクリックしてください |
| ORS の利用上限に達した | 429 | しばらく待ってからお試しください |
| 標高がすべて取れない（国外や海上） | 422 | 標高データは日本国内のみです |
| `ORS_API_KEY` が設定されていない，その他 | 500 / 502 | 経路を計算できませんでした |

標高が一部だけ欠けた場合は，近くの有効な値で埋める（旧版は0mとして扱っていたため，断面図に崖のような段差ができていた）．

## 5. 画面の状態

`planner.tsx` で，画面を4つの段階に分けて管理する．

```
idle ──出発地点を選ぶ──▶ drawing ──経路を確定する──▶ loading ──成功──▶ result
  ▲                       ▲                            │
  │                       └──────────失敗（エラー表示）─────┘
  └──────────────やり直す（どの段階からでも）──────────────
保存済みルートをクリック ──▶ result（保存済みなので「保存」は押せない）
```

- **保持する値**：経由点，API の結果，表示中の保存済みルートの ID，体重，保存済みルートの一覧，エラー．
- **計算で出す値**：統計は「API の結果 × 体重」から計算する．

### 画面の配置

- PC：上にヘッダー，中央の左が地図，右が保存済みルートの一覧，下に操作バー．
- スマホ：地図，一覧，操作バーを縦に並べる（旧版はスマホに対応していなかった）．
- 部品は shadcn/ui のもの，色は旧版のモスグリーンを primary に引き継ぐ．

## 6. 環境変数

| 変数 | 用途 | このフェーズで使うか |
|---|---|---|
| `ORS_API_KEY` | ORS の経路探索（サーバー側でのみ使う．`NEXT_PUBLIC_` を付けない） | 使う |
| `DATABASE_URL` | Postgres の接続先 | 使わない（次フェーズ） |
| `BETTER_AUTH_SECRET` / `BETTER_AUTH_URL` | 認証 | 使わない（次フェーズ） |

国土地理院の標高 API と OpenStreetMap の地図タイルにはキーが要らない．

## 8. テスト

- **Vitest**：設定ファイル `vitest.config.mts` を新しく作る．対象は `lib/` の純粋な関数（距離，間引き，エネルギーモデル，時間の表示，欠けた標高の補完）．
- **Playwright**：今ある Playwright 公式サイト向けのサンプルテストを，このアプリのテストに置き換える．ORS への通信は `page.route` で差し替えるので，CI に API キーは要らない．
- **確認するもの**：`biome check`，`tsc`，`next build` が通ること．
