# DB フェーズ 設計書

移植フェーズ（`docs/design.md`）と UI の改修のあとに行う，ログイン・ルートのクラウド保存・共有・利用回数の制限の設計．

## 1. ゴールと範囲

| 含める | 含めない（後回し） |
|---|---|
| メールアドレスとパスワードでのログイン（better-auth） | GitHub・Google などの外部ログイン（各サービスでのアプリ登録が必要なため） |
| ログインした人のルートを DB（Neon）に保存 | パスワードを忘れたときの再設定（メール送信の仕組みが必要なため） |
| ブラウザに保存したルートをアカウントに取り込む | ルートの編集（名前の変更と共有の切り替えだけ行う） |
| ルートを URL で共有（ログインしていない人も見られる） | |
| `/api/plan`・`/api/geocode` の利用回数の制限 | |

**方針**：ログインしなくても全機能を使える．ゲストの保存先は今までどおりブラウザ（localStorage）で，ログインすると DB に保存し，端末をまたいで使え，共有もできる．

## 2. 全体構成

```
ブラウザ ─┬─ /api/auth/*           better-auth（登録・ログイン・ログアウト・セッション）
          ├─ /api/routes           自分のルートの一覧・保存（ログイン必須）
          ├─ /api/routes/import    ブラウザのルートをまとめて取り込む（ログイン必須）
          ├─ /api/routes/[id]      名前の変更・共有の切り替え・削除（持ち主のみ）
          ├─ /api/plan, /api/geocode   利用回数を数えてから ORS などを呼ぶ
          └─ /r/[id]               共有ページ（共有中なら誰でも見られる）
                     │
                     ▼
               Neon（Postgres，シンガポール）← Drizzle ORM + postgres.js
```

### DB への接続

- アプリは `DATABASE_URL`（コネクションプーリング経由）に postgres.js でつなぐ．プーリング（PgBouncer のトランザクションモード）では準備済み文を使えないので `prepare: false` にする．
- テーブルの作成・変更（drizzle-kit）は `DATABASE_URL_UNPOOLED`（直接接続）を使う．
- 接続は最初に使うときに作る．`DATABASE_URL` がない環境（CI のビルドなど）でも，DB を使わない画面やテストは動くようにする．

## 3. テーブル

better-auth の4つのテーブル（`user`，`session`，`account`，`verification`）は CLI で生成する．アプリ独自のテーブルは次の2つ（better-auth のログインの回数制限用に `rate_limit` も CLI で生成される）．

### `routes`：保存したルート

| 列 | 型 | 説明 |
|---|---|---|
| `id` | uuid（主キー，自動生成） | 共有 URL にも使う．推測されにくい |
| `user_id` | text（`user.id` への外部キー，ユーザー削除で一緒に消す） | 持ち主 |
| `name` | text | ルート名（50文字まで） |
| `coords` | jsonb | 地図に描く経路の座標列 |
| `profile` | jsonb | 断面図・統計用の点と標高 |
| `stats` | jsonb | 保存した時点の体重での統計（一覧の表示用） |
| `shared` | boolean（初期値 false） | true なら共有 URL で誰でも見られる |
| `created_at`，`updated_at` | timestamptz | |

索引：`(user_id, created_at)`．1人あたり最大 200 件．

### `api_usage`：API の利用回数（better-auth のログイン用の `rate_limit` とは別）

| 列 | 型 | 説明 |
|---|---|---|
| `key` | text | 例：`plan:ip:203.0.113.1:minute`，`plan:global:day` |
| `window_start` | timestamptz | 数え始めの時刻（1分単位・1日単位に切り捨て） |
| `count` | integer | 回数 |

主キー：`(key, window_start)`．`insert … on conflict do update set count = count + 1 returning count` の1文で数える．

## 4. 利用回数の制限

ORS の無料枠（経路 2,000回/日，地名検索 1,000回/日）を，連打や自動アクセスで使い切られないようにする．

| API | 1つの IP あたり | 全体 |
|---|---|---|
| `/api/plan` | 10回/分，150回/日 | 1,500回/日（ORS の枠の 75%） |
| `/api/geocode` | 20回/分，200回/日 | 450回/日（1回の検索で ORS を2回呼ぶため） |

- 超えたら 429 と「しばらく待ってから」のメッセージを返す．画面には今のエラー表示の仕組みで出る．
- IP は Vercel が付ける `x-forwarded-for` の先頭を使う．
- DB に一時的につながらないときは制限をかけずに通し，ログに残す（アプリが使えなくなるのを避ける）．
- ログインまわり（`/api/auth/*`）は better-auth の制限機能を使い，回数は DB に保存する．

## 5. API

すべて JSON．入力は zod で検査する．

| メソッドとパス | 権限 | 内容 |
|---|---|---|
| `GET /api/routes` | ログイン | 自分のルートを新しい順に返す |
| `POST /api/routes` | ログイン | ルートを保存する．本文は `{ name, coords, profile, stats }` |
| `POST /api/routes/import` | ログイン | ブラウザのルートをまとめて保存する（最大50件） |
| `PATCH /api/routes/[id]` | 持ち主 | `{ name?, shared? }` を変える |
| `DELETE /api/routes/[id]` | 持ち主 | 削除する |

権限がないときは 401（未ログイン）か 404（他人のルート．存在を知らせない）を返す．

## 6. 画面

- **パネルの見出し**：右上に「ログイン」ボタン．ログイン中は名前の頭文字の丸いボタンで，押すとメニュー（名前・メールアドレス・ログアウト）．
- **ログインのダイアログ**：「ログイン」と「新規登録」のタブ．新規登録は名前・メールアドレス・パスワード（8文字以上）．
- **保存済みタブ**
  - ゲスト：ブラウザのルートを表示し，「ログインすると，端末をまたいで保存・共有できます」と案内する．
  - ログイン中：DB のルートを表示する．各ルートに「共有」の切り替えと「リンクをコピー」．ブラウザにルートが残っていれば「このブラウザのルートを N 件取り込む」ボタンを出す．
- **共有ページ `/r/[id]`**：ルート名・作成者名と，地図・統計・断面図を表示する（読み取り専用）．「自分でもルートを作る」でトップへ．共有されていない・存在しないルートは 404．ページのタイトルと説明にルート名と距離を入れ，SNS などで共有したときに分かるようにする．

## 7. 環境変数

| 変数 | 値 | 登録先 |
|---|---|---|
| `DATABASE_URL`，`DATABASE_URL_UNPOOLED` | Neon（Vercel の連携で自動登録済み） | Vercel（本番・プレビュー），手元の `.env` |
| `BETTER_AUTH_SECRET` | ランダムな32バイト | Vercel（本番・プレビュー），手元の `.env` |
| `BETTER_AUTH_URL` | 本番の URL / `http://localhost:3000` | Vercel（本番のみ），手元の `.env` |

プレビュー環境では `BETTER_AUTH_URL` を設定せず，Vercel が付ける `VERCEL_URL` から組み立てる．

## 8. マイグレーション（テーブルの作成・変更）

- `drizzle-kit generate` で SQL を作り，`drizzle/` に置いてコミットする．
- Vercel では `vercel-build` スクリプトで `drizzle-kit migrate` してからビルドする．本番とプレビュー（Neon のブランチ）のそれぞれに自動で適用される．
- CI（GitHub Actions）は DB を使わないので，今の `build` のまま．

## 9. テスト

- **ユニット**：利用回数の窓の計算・IP の取り出し・入力の検査．
- **E2E**：ゲストの流れ（今のテスト）はそのまま通ること．DB を使う流れは CI に DB がないので，API を差し替えてログイン中の画面（保存済みタブ・共有の切り替え）を確かめる．
